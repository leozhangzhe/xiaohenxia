# 比赛启动、演示和数据说明

## 初始化和迁移

推荐 README 的桌面启动器：新工作区创建独立 MySQL，随机数据库密码仅以 Windows DPAPI 密文保存。首次创建管理员使用控制台输入，其余用户通过真实注册创建。应用启动执行缺表创建和幂等字段/状态迁移；申请旧模拟承诺被识别后替换为“历史模拟记录，平台提交情况未经核实，需人工跟进。”，正常人工备注保留。**不导入开发者数据库。**

外部 MySQL：在当前进程环境提供 SF_AUTH_MYSQL_*，隐藏输入 SF_AUTH_ADMIN_PASS，执行 `.venv\Scripts\python.exe -B scripts/auth_admin.py --initialize`，移除管理员密码变量后运行 scripts/start-local.ps1。首次建库需要建库/表及读写权限。详见 docs/auth-stage1.md。扫描和检索 SQLite 表由应用初始化，桌面启动器自动指定项目内路径。

升级前停服并备份自己的整个工作区；迁移不等于跨版本无损回滚。回退源码需配套恢复同一时点数据。新电脑应重新初始化，不复制旧 DPAPI 凭据。

## 8–10 分钟演示

1. 真实注册 demo_user_a / demo_user_b，现场设置密码；展示错误密码、刷新保留会话、退出失效。
2. 总览和入口：解释域名/网站/IP、用户名、邮箱对应来源，以及来源和覆盖限制。
3. SpiderFoot：对本人或授权域名进行最小 DNS 扫描，展示原生任务和结果。example.com 是文档保留域名，不是选手自己的资产。网络不可用时展示真实失败，不伪造命中。
4. 统一检索：用户名用获授权的公开测试名；邮箱可用 alice@example.invalid 验证输入和无结果语义，不能预期存在真实注册信号。各来源独立状态，取消应终止所属进程；HIBP 没 Key 显示未配置。
5. 本地样例：alice@example.invalid 命中合成记录；no-match@example.invalid 显示“当前数据源未发现匹配，不代表不存在相关信息。”。明确是本地 SQLite 合成样例库，不是实时互联网数据。
6. 用户隔离：A 创建任务，B 不可见；直接使用 A 的任务 ID 也应被拒绝。
7. 申请记录与人工跟进：对 example.invalid 合成目标创建隐藏/删除申请，勾选确认，初始已记录。管理员手工维护备注及状态；普通用户不能处理。未实际联系平台不要选择已联系平台。这不是自动删除，不保证平台执行。
8. Ctrl+C 安全停止，同目录再次启动，重新登录后账号、扫描、任务和申请仍在。

## 合成数据

data/leak-check.db 保留原 schema、字段和索引，person 仅两条合成记录，姓名“测试用户一/测试用户二”，邮箱 alice@example.invalid / bob@example.invalid。手机号、身份证、QQ 字段均 NULL；来源为“本地合成演示数据 / 非真实泄露事件”。无预置 MySQL 账号或历史查询任务。测试源码中的固定账号/密码/结果是隔离夹具，不是比赛默认账号。

不要运行旧 import_leak_data.py 重新导入历史数据；它保留显式确认保护。合成数据不冒充外部查询结果。

## 已知限制和排障

- 实时来源依赖网络、规则、验证码及平台策略；失败、超时和无匹配均可能出现。结果需要人工核验，无法证明身份或全网查全，不提供无依据综合安全评分。
- HIBP 需自行取得 Key，本包没有密钥；Holehe 是可能注册信号，不是泄露证据。
- 初装需要 Python 包仓库和 WhatsMyName 官方规则可达；源码包不含解释器、MySQL 二进制、工具虚拟环境。比赛前按 README 安装。
- Bootstrap 3 / jQuery 等旧依赖为兼容现有功能保留，不建议直接暴露到公网。公网 HTTPS、TLS、限流、灾备、生产集群不属于本次交付。
- 仅 Windows x64 / Python 3.12 / MySQL 8.0.46 冷启动受支持；Docker 历史配置不是本包认证入口。
- 桌面启动需要一个空闲 Q–Z 盘符解决 Windows MySQL 中文路径问题。端口占用应先确认已有实例；启动器不会关闭其他 Python/MySQL。
- 日志和数据只在本地运行目录；备份前停服。不要只复制 DPAPI 文件到其他用户/电脑。
- WebGL 不可用、移动端、软件渲染和 reduced-motion 会降画质或静态化，功能不依赖动效。
- 安装/启动失败保留文件检查日志；不要删除数据目录重试，不应靠内存账号伪装成功。
