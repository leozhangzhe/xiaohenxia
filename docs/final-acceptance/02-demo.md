# 最终演示流程（约8分钟）

## 赛前

在独立演示工作区初始化管理员并真实注册两个合成用户。使用本人设置的密码，先完成依赖检查、普通重启和外网可达性检查。不要把开发数据库拷到演示电脑。准备本地合成命中和失败备用讲解；演示前再次确认地址对应正确工作区。

## 演示顺序

1. **认证（1分钟）**：注册/登录demo_user_a，展示错误密码、刷新后仍登录、退出失效。说明账号保存在MySQL且密码哈希存储；不展示密码或配置密文。
2. **总览和检索入口（1分钟）**：说明域名/网站/IP对应SpiderFoot，用户名对应Sherlock/Maigret/WhatsMyName，邮箱对应Holehe/HIBP。说明只检索本人或获授权的目标。
3. **真实检索（2分钟）**：用合成公开用户名和文档保留域名example.com / example.invalid；每个来源独立显示状态、查询时间和限制。只有实际命中才展示来源链接，不把同名当本人。失败、部分完成、未配置如实讲解，不反复查询追求好看结果。
4. **统一结果（1分钟）**：筛选来源/结果类型，查看来源、时间、原始链接及可信说明。ROOT和输入种子不作为外部发现；空结果不等于安全。
5. **合成样例（1分钟）**：alice@example.invalid命中、no-match@example.invalid无匹配。明确本地SQLite合成样例库、非真实泄露事件、不是实时互联网查询。Holehe的注册信号不是泄露记录。
6. **用户隔离（1分钟）**：A创建任务/申请，退出换B，列表不可见；直接使用A的资源ID也应拒绝。不能只依靠隐藏按钮证明权限。
7. **人工跟进（1分钟）**：A对example.invalid合成目标保存申请并确认说明；普通用户不能修改处理状态，管理员记录备注。没有联系平台就保持已记录/待人工处理，不演示假的平台处理中或完成。

可追加：正常Ctrl+C停止，再启动并重新登录，记录仍存在。演示窗口不足时展示此前正常重启的记录，并明确它是保存的本地记录。

## 固定讲解边界

“当前数据源未发现匹配，不代表不存在相关信息。”

“这是申请记录与人工跟进，不是自动删除，不保证第三方执行，需要人工联系或用户自行联系平台。”

HIBP没有Key时展示未配置、不发送请求。手机号、身份证、QQ不属于统一入口的全网检索能力。任何录屏、截图或预录内容必须标注采集时间及合成/历史属性，不能冒充现场实时检索。
