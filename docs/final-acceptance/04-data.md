# 演示数据说明

## 允许的合成输入

- 用户名：自行生成 `xhx_demo_` 加随机字母/数字，不使用真实个人账号。
- 邮箱：alice@example.invalid、bob@example.invalid、no-match@example.invalid。
- 域名：example.invalid；example.com是文档保留域名，不是参赛者自有资产。
- 申请目标：`https://example.invalid/synthetic-demo`，备注标“合成演示，无真实平台提交”。

随机字符串仍可能偶然与公网账号同名；命中不证明身份，需人工核验。不要把解析到的地址直接当作可靠数字痕迹证据。

## 附带SQLite样例

data/leak-check.db保留兼容表结构、字段和索引。person只有两条合成记录：测试用户一/测试用户二，邮箱均为example.invalid。手机号、身份证、QQ和其他个人字段均NULL，来源明确为本地合成演示数据/非真实泄露事件。无匹配不代表安全。

这个库不包含现存账号、互联网采集结果或真实泄露资料。不要运行旧导入脚本重新导入历史个人数据，也不要随机分配看似真实的泄露来源。

## 干净工作区

在新目录解压干净源码，用安装脚本重建依赖，再首次启动初始化数据库、真实注册A/B。演示记录通过真实页面创建，不直接写入伪造实时结果。已有工作区保留，不清空、不混拷数据库，也不复用Windows DPAPI密文到其他电脑。

实验/验收数据仅存项目内独立运行目录，排除出Git和提交ZIP。若需要展示旧扫描或录屏，明确标注“已保存结果”及原查询时间，不称为现场实时结果。
